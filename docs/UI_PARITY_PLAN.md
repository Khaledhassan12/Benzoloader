# UI parity plan (core acceptance criterion from Khaled, 25 Nov 16:09)

His instruction: the Benzoloader UI/UX must be extremely close to the screenshots he supplied. Scope: app UI only. The captures are a design reference. They are not published, and nothing in the app may copy their text strings, icons or other assets: layout, structure, order, spacing and colour behaviour are matched, words and icons are written independently. No advertising anywhere in the app (unchanged rule). Nothing below has been rendered or run: every statement about the current app is read from layout and theme files, and visual equivalence is UNVERIFIED until screens can be rendered and compared side by side (final stage, after the build gate lifts).

- Custom colour research (source: Material Components Android 1.12.0, DynamicColors.java and ColorResourcesOverride.java on raw.githubusercontent.com): applyToActivityIfAvailable returns immediately unless isDynamicColorAvailable(); that method is false below Android 12 (S), true from Android 13, and on 12 and 12L only for a built-in list of manufacturers and brands. The library's own seed-colour path (DynamicColorsOptions content-based source, which builds a SchemeContent from a seed with Material colour utilities) sits behind the same gate, and the colour override it uses has its own checks for Android 11 and newer. So through the library's public entry point a user-picked seed works only where dynamic colour is available; it is NOT a path for Android 8 to 11. Platform wallpaper colours (the system's Dynamic Color) and library-generated palettes from a user seed are two different things. Not yet researched: whether the library's colour utilities classes can be called directly to compute a scheme on any version, and how a computed scheme would be applied to views without resources override (that needs its own design). Current state: PARTIAL theme support. Device colours plus four fixed presets; no user-picked colour yet. Also: progress bars, drawer header, floating buttons and bar badges now use theme roles; status icons stay fixed; dark_mode setting is stored and unread; no manual light/dark/system switch exists.
