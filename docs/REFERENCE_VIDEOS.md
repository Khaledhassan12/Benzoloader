Owner request (Khaled, 25 Nov 20:36): one Markdown file in the project recording every detail of the reference videos, as precisely as possible, updated with each new video.
This file is documentation of OBSERVATION. It is not a claim that the app matches. Labels used everywhere:
- OBSERVED: seen in a frame. INFERRED: my reading, not seen. UNCLEAR: not readable or not shown. NOT SEEN: no frame covers it.
- Implementation status is kept in the last section and in docs/PROGRESS_LOG.md. Nothing here is built, rendered or run unless the log says so (last compiled commit: fd59931; everything later is written, unbuilt).
- Method limits: videos were reviewed as review encodes (400x880) using contact sheets (every 6 to 10 s) plus full-size frames at chosen points. Quick taps between sampled frames can be missed. Where a sentence says "seen", a frame showed it.
- Rules kept: the reference app's code, strings, assets, sample file names and sample URLs are not copied. Labels below are described in my own words where they are generic; UI parity means layout, order, structure and behaviour only. No access to the reference app's internals is claimed.

## Cross-video concepts (what the videos together mean)
1. Two side menus. END edge (as the user's right menu): filter panel with Category, Status, Time, Sorting; sections open independently; counts; title follows the category; marks for custom sort or time. START edge (left menu): a quick-settings panel with a speed graph, a progress bar, collapsible sections (Downloading, Torrent, Notifications, Options, Interface, Tools, App) and a three-button bottom bar (Exit, Settings, Browser). The "Swap side menus" switch exchanges the edges (observed in the panel Interface section and as a Browser-area row in the settings capture).
2. The quick-settings panel and the settings screens read the SAME stored values (seen: a dialog set Threads to 16 and the panel showed 16). So the panel is a second view of settings, not a separate store. OBSERVED.
3. The eye icon, in the panel header, in Properties and in the Editor, is a visibility editor: checkboxes appear beside rows; unchecking changes what is shown. OBSERVED that rows change; persistence NOT SEEN.
4. The list has a user-editable stored order: Up, Down, To top, To bottom exist in the selection overflow. OBSERVED. Sort "Apply" (refresh icon on the Sorting header, then "Apply sorting?" Cancel/OK, then a "saved" toast) most likely writes the sorted sequence as the new stored order: INFERRED.
5. Settings screens follow one pattern: switch rows (title, grey sub-line, switch), value rows (title, accent-coloured value), dialogs for sliders (min, typed value, max), radio lists, checkbox lists, and a colour picker. Dependent rows dim while their parent is off. OBSERVED.
6. Individual-settings gate on Interface: colour rows below it dim until the gate is on; a red cross appears on rows that differ from default. OBSERVED.
7. Bottom bars: the list bar (seven icons: power, settings, browser, add, play, stop, list with badge) is separate from the panel bar (Exit, Settings, Browser). INFERRED reading of "Bottom action bar for list" vs "in left menu"; consistent with all captures but no tap proved it.
8. Torrent label in the filter panel means "came from a torrent" (INFERRED from counts overlapping type counts).

### Dense-frame follow-up (video, 2 s frames around the sort dialog, 3 s frames around the eye icon)
RESOLVED from the frames:
- Sorting: tapping a sort row applies it to the list at once (list reorders, title gets the sort mark). The "Apply sorting?" dialog does not come from a row tap: it comes from tapping the refresh-style icon on the Sorting header, which is visible only while a non-default sort is chosen. After OK the toast "saved" appears, the title mark goes away, the Order (down) row is selected, and the list keeps the order the sort produced (the rows were all of one type after a Category sort). INFERRED from that: OK makes the current sorted sequence the new stored add-order. Not built: it needs a stored order column (Room migration), and until it is built the app must not show a refresh icon or dialog that does nothing.
- Eye icon: tapping it puts a checkbox beside every section header and every row, all checked. No unchecked state or filter change appears in the frames, and the list does not change. INFERRED: it is a visibility editor for panel entries, not a multi-select filter (correcting my earlier note). Not built.
- Torrents: choosing it shows rows of many file types (each with its own type icon) and the count (879) overlaps the type counts, so it means "came from a torrent". Written: ListLogic.inCategory, used by the list filter and the panel counts, 1 test written, not run.
STILL UNRESOLVED: what Stopped maps to (the Stopped list was empty in the capture, so it stays Paused as an inference), whether hidden panel entries persist.
